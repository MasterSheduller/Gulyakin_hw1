# HW1. Диалоги с языковыми моделями

## Разведочный анализ

- Загружено 10 000 диалогов.
- Язык: ~99% английский, несколько десятков русских.
- Среднее число реплик пользователя — около 3.
- Метки реакции несбалансированы: `neutral` ~78%, `negative` ~12%, `positive` ~10%.
  Из-за дисбаланса основная метрика — macro-F1, accuracy приводится рядом.
- Разметки тем в данных нет; в `labels.user_turns` есть поле `task_type`,
  на нём и построены темы (см. задачу 2).

## Чистка

- Нормализация текста: нижний регистр, выделение слов регуляркой `[^\W\d_]+`,
  определение языка по доле кириллицы, удаление стоп-слов (`nltk.stopwords`),
  стемминг (`SnowballStemmer`). Реплики пользователя склеиваются в один текст;
  реплики ассистента в признаки не попадают.
- Пустых реплик ассистента не обнаружено.
- Явных дубликатов по `dialog_id` нет.
- Объект разбиения — диалог (`dialog_id`), поэтому утечки между train и test нет
  и достаточно обычного стратифицированного разбиения.

## Задача 1. Реакция

- Метрика: macro-F1 (из-за дисбаланса классов), дополнительно accuracy.
- Валидация: 80/20 train/test со `stratify=y`, 5-фолдовая `StratifiedKFold`
  на train для выбора модели; тестовый сет используется один раз.
- Модели (все на TF-IDF, `max_features=5000`):
  - `dummy_most_frequent` — baseline из семинара 1;
  - `dummy_stratified` — случайный baseline в пропорциях классов;
  - `multinomial_nb` — наивный Байес, семинар 1;
  - `linear_svc` — SVM, семинар 3;
  - `logistic_c01` — логистическая регрессия с `C=0.1` (своя модель на базе семинара 3).
- Результаты кросс-валидации:

| Модель | F1-macro (CV) |
|:--|--:|
| `dummy_most_frequent` | 0.2477 |
| `dummy_stratified` | 0.3334 |
| `multinomial_nb` | 0.3985 |
| `linear_svc` | **0.4851** |
| `logistic_c01` | 0.3003 |

- Лучшая модель: `linear_svc` (F1-macro = 0.4851).
- Метрики на тесте:

| Метрика | Значение |
|:--|--:|
| accuracy | 0.6267 |
| F1-macro | 0.4970 |

- `classification_report` и матрица ошибок — в выводе `analysis.py`.

## Задача 2. Темы

Готового списка тем в данных нет, поэтому темы построены на поле `task_type`
из `labels.user_turns`. Взяты четыре самых частых `task_type` в обучающем наборе:

- `information_seeking` — пользователь задаёт вопрос и ждёт факта или объяснения.
- `creation` — просит сгенерировать текст, код, идеи.
- `analysis` — просит разобрать, сравнить или оценить что-то.
- `open-ended_discovery` — свободное исследование темы без чёткой задачи.

Тема диалога = самый частый `task_type` среди реплик пользователя; если ни одна
реплика не попадает в top-4, диалог получает метку `other`.

- Метрики: на своей валидации — accuracy и macro-F1 (как прокси).
  На скрытом тесте по темам считаются метрики разбиений
  (ARI, NMI, однородность, полнота, V-мера, чистота) — они реализованы
  в `solutions_utils.compute_partition_metrics` и используются при наличии
  меток `topic`.
- Модели и валидация те же, что в задаче 1.
- Результаты кросс-валидации:

| Модель | F1-macro (CV) |
|:--|--:|
| `dummy_most_frequent` | 0.1895 |
| `dummy_stratified` | 0.2450 |
| `multinomial_nb` | 0.2850 |
| `linear_svc` | **0.3548** |
| `logistic_c01` | 0.2224 |

- Лучшая модель: `linear_svc` (F1-macro = 0.3548).
- Метрики на тесте:

| Метрика | Значение |
|:--|--:|
| accuracy | 0.6833 |
| F1-macro | 0.3642 |

- Распределение предсказанных тем на прогоне (`predictions.csv`):
  `information_seeking` — ~86%, `creation` — ~12%,
  `open-ended_discovery` — ~1.3%, `analysis` — ~0.7%,
  `other` — 0% (модель ни разу не предсказала этот класс).

  к информационному запросу, чем к аналитическому.

## Ограничения

- Темы опираются на `task_type`, а не на предметную область; это допущение,
  потому что другой разметки в данных нет.
- Дисбаланс реакции (neutral ~78%) приводит к тому, что baseline
  `dummy_most_frequent` даёт высокую accuracy при низком macro-F1
  по редким классам; поэтому основная метрика — macro-F1.
- На скрытом тесте распределение тем и реакций отличается от обучающего,
  поэтому метрики на своей валидации — оптимистичная оценка.
- Класс `other` в темах — catch-all для диалогов, где ни одна реплика
  пользователя не попала в top-4 `task_type`. На прогоне `predictions.csv`
  модель ни разу не предсказала `other`, а класс `analysis` предсказывается
  крайне редко (~0.7%) — значит, на новых данных классификатор тем
  сильно смещён в сторону `information_seeking`. Это ожидаемо при таком
  дисбалансе и ограничивает качество по метрикам разбиений.
